## Question (#28)
Every existing `.mcp.json` entry is a stdio server (`command`+`args`+`${STATIC_TOKEN}`). Can remote-OAuth
connectors (Canva, Gmail) be expressed as STATIC scaffold config? This gated the coo/cmo/revenue profiles (#30).

## Finding (verified via code.claude.com/docs/en/mcp)
- **`.mcp.json` DOES support remote servers**: `{"type":"http","url":"..."}` (also sse/ws). A `url` with
  NO `type` is a config ERROR (Claude Code reads it as stdio and skips it). `env`/`url`/`headers` support `${VAR}`.
- **OAuth is interactive, config is static**: no token in the file. Claude Code detects 401/403, user completes
  the browser flow via `/mcp` or `claude mcp login <name>`; tokens live in the OS keychain. Two constraints that
  are NOT derivable from the env-scan and must be printed: (a) project-scoped servers sit at "pending approval"
  until the user approves on first interactive `claude` run (already true for our stdio servers too); (b)
  non-interactive `claude -p`/SDK runs can't complete OAuth → tools unavailable until a human signs in.
- **Canva → (A) STATICALLY EMITTABLE**: `{"type":"http","url":"https://mcp.canva.com/mcp"}`. Uses OAuth Dynamic
  Client Registration, so Claude Code's local `/mcp` flow works. **No `${VAR}` → scanRequiredEnv/KEY_SOURCES need
  NO change** (correct — Canva needs nothing in .env.local; the connect step is interactive, printed in printNextSteps).
- **Gmail → (B) NOT STATICALLY EMITTABLE**: Claude Code docs explicitly list Gmail/M365/Google Calendar as NOT
  supporting local OAuth (the IdP only accepts claude.ai's redirect URL). Must be connected at claude.ai →
  Settings → Connectors. Emitting a gmail `.mcp.json` entry produces a BROKEN server → violates "emit config
  that works." Fallback: printNextSteps prints "connect Gmail via claude.ai Connectors" (no profile ships it yet).

## Applied (#30)
- **cmo** ships with `templates/cmo/.mcp.json.partial.hbs` = `{"mcpServers":{"canva":{"type":"http","url":"https://mcp.canva.com/mcp"}}}`.
  extraMcp:['canva']. printNextSteps: `if (profile.extraMcp.includes('canva'))` → prints the interactive `/mcp`
  Canva sign-in + project-approval note (ux.ts). The env-scanner correctly surfaces NO canva token.
- No Gmail-dependent profile ships. Any future one gets guidance-only (connectors), not a `.mcp.json` entry.

## Caveats (Rule 12)
- Canva URL `https://mcp.canva.com/mcp` confirmed via secondary sources (canva.dev/mcpservers.org/composio); the
  primary canva.com/help page 403'd. Re-confirm against canva.dev/docs/mcp before a wider rollout.
- Known Claude Code bugs (#3273/#38102/#26675) around pre-configured OAuth clientId on HTTP servers do NOT affect
  Canva (it uses DCR, no pre-config) but would bite a future connector lacking DCR.
