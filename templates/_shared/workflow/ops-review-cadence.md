### Operations Review Cadence (Metrics → Diagnose → Assign → Follow-up)

A recurring operating rhythm, not a one-off document. The loop repeats every cycle (weekly / monthly). For a genuine one-off strategic call, use the executive-decision workflow instead. Numbers come from the source system, never from memory (Rule 13); owners and dates are named, not implied.

#### Phase 1 — Pull the metrics
Gather the operating numbers for the period from their source systems (dashboards, tickets, SLAs, throughput) — every figure cites where it came from, and a gap is marked `?` rather than guessed.

#### Phase 2 — Diagnose
Compare against target and prior period, and explain the notable moves — what is off, by how much, and the likely cause. Keep conflicting explanations visible instead of averaging them into one (Rule 7).

#### Phase 3 — Assign owners & actions
Turn each issue into a concrete action with a **named owner** and a **due date**. An action with no owner or no date is not an action — surface it as still-unassigned (Rule 12). The human assigns; the assistant drafts.

#### Phase 4 — Scheduled follow-up
Record the actions and set the next review checkpoint, so last cycle's commitments are the first thing checked next cycle. Archive the review so the operating history is retraceable.

### Definition of Done
The review is done when every metric traces to its source, each issue has a named owner and a due date, and the follow-up checkpoint is scheduled with the prior cycle's actions carried forward. An action with no owner/date, or a number with no source, is not done — say so plainly (Rule 12).
