# Operations review playbook

An operations review turns numbers into decisions and decisions into owned actions. A review that lists metrics without owners is a status report, not a review. Use this skill any time you run one or review the draft before it circulates.

## Metrics come from a source

Every metric in the review is pulled from a named **source** — a dashboard, a system of record, a ticket queue. Never guess a number or recall one from memory (Rule 13). Show each metric against its target, and name where it came from. If a number isn't in hand, mark it `[SOURCE TBD]` and surface the gap — do not launder an estimate into a precise-looking figure.

## Diagnose before you prescribe

For every metric that moved, ask *why* before proposing an action. Tie each action to the metric or blocker it addresses. An action with no metric behind it is activity theatre; a metric that moved with no diagnosis is an unanswered question — surface it either way.

## Every action has an owner and a due date

This is the core discipline. Each action item carries a named **owner** — a person or role accountable, not "the team" — and a due date. An action with neither is surfaced as unassigned, never quietly saved. If no one will own it, that itself is a finding to raise, not to bury.

## Follow up on prior actions

Open the review by carrying forward last period's action items and their status: done, in progress, or slipped. An action assigned and never checked trains everyone to ignore the next one. Slipped actions get a reason and a new due date, or an explicit decision to drop them.

## Structure

1. **Summary** — the one or two things that matter most this period.
2. **KPIs vs target** — each metric, its target, and its source.
3. **What moved and why** — diagnosis, not just deltas.
4. **Risks & blockers** — what threatens next period.
5. **Action items** — each with a named owner and a due date.

## Review checklist (before the review circulates)

- Every metric shows its source; every gap is a visible `[SOURCE TBD]`, not a guess.
- Each moved metric has a diagnosis, not just a number.
- Every action item has a named owner and a due date; unassigned actions are surfaced.
- Prior action items are carried forward with status.
- Conflicting priorities are named for a human to resolve, not averaged (Rule 7).
